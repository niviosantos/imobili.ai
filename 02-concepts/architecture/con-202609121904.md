# Open-Source Sovereignty and Self-Service Multi-Tenant Architecture

This note establishes the open-source governance and strict data isolation model of Imobili.ai.

---

## Definition

Open-Source Sovereignty and Self-Service Multi-Tenancy is an architectural model where the core software stack is distributed under permissive open licenses, allowing real estate brokerages to independently deploy, own, and operate segregated tenant instances with absolute logical data isolation and guaranteed absence of shared listing pools.

---

## Rationale

Commercial real estate software is dominated by closed, monolithic vendors that enforce predatory subscription fees, trap broker customer relationships in proprietary databases, and create artificial friction during onboarding. Sovereign, self-service architecture ensures that brokerages own their data assets, agent models, and digital customer channels. Strict rejection of shared listing pools protects proprietary agency inventory from competitor scraping and leakage.

---

## Rules and constraints

1. **Permissive Open-Source Licensing:** All core schemas, protocols, APIs, and foundational deployment templates must remain open source without proprietary runtime gates.
2. **Autonomous Provisioning:** Tenant setup must execute deterministically via self-service command-line interfaces or automated scripts without requiring human sales intervention.
3. **No Shared Pools (Strict Isolation Invariant):** The platform explicitly prohibits cross-tenant federated search pooling or aggregated multi-brokerage shared vector collections. Each tenant instance operates with completely segregated databases and dedicated vector indexes per [[req-202609121910]].
4. **Data Portability:** Tenants must possess the capability to export their full property inventory, vector embeddings, and audit logs at any time in standardized formats.
5. **Client-Side Federation Boundary:** The Imobili.ai server architecture delegates all multi-agency search federation, cross-brokerage ranking, and listing deduplication to external consumer client agents. The server platform does not maintain or execute server-side federated search pools.

---

## Examples

1. **Self-Service CLI Onboarding:** A new agency initializes an isolated production tenant with dedicated TLS endpoints and vector collections in under 5 minutes using `imobili-cli tenant provision`.
2. **Closed-Boundary Tenant Operations:** Brokerage Alpha operates its dedicated instance at `alpha.imobili.ai`; queries submitted to Brokerage Alpha can only access listings within `imob_alpha_vectors`, with zero possibility of cross-querying or federating with Brokerage Beta.
