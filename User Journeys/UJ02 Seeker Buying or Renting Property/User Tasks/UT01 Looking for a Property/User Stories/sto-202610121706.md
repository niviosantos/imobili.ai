# User Story: Dynamic Amenity Proximity and Transit Layer Exploration

---

## Summary

- **As a** property seeker evaluating living quality in candidate neighborhoods,
- **I want to** toggle specific amenity proximity layers (schools, bakeries, grocery stores, pharmacies, gyms, public transit lines and stations) on the Living Map Canvas,
- **So that** I can visually inspect surrounding infrastructure, calculate walking times, and confirm daily conveniences before choosing a property.

---

## Scope in/out

- **In Scope:** Interactive UI toggle controls for individual amenity categories (schools, bakeries, grocery stores, pharmacies, gyms, public transit lines and stations), rendering amenity icons and layers on the Living Map Canvas per [[con-202609121903]], calculating pedestrian walking distances and multimodal isochrones (5, 10, 15-minute pedestrian network buffers), rendering transit lines (metro, train, bus routes), and displaying proximity distance metrics on property cards.
- **Out of Scope:** Inspecting internal property photos/videos (handled in [[sto-202610121707]]) and submitting visit appointments.

---

## Preconditions

1. Living Map Canvas spatial engine active per [[con-202609121903]].
2. Verified Points of Interest (POI) and transit routing datasets loaded into tenant spatial GIS services.
3. Property candidate coordinates or neighborhood centroids available from search results.

---

## Expected behavior

When a seeker selects one or more amenity categories (e.g., bakeries, pharmacies, metro lines), the Living Map Canvas renders dynamic spatial overlays showing nearby amenity locations, walking distance buffers around the selected property, and active transit paths. Property inspection panels display quantified proximity badges (e.g., "350m do Metrô", "Padaria a 120m").

---

## Acceptance criteria

### Criterion 1: Categorical Amenity Layer Toggles
- **Given** the Living Map Canvas displaying candidate properties,
- **When** the seeker toggles one or more amenity checkboxes:
  - Schools (`escolas`)
  - Bakeries (`padarias`)
  - Grocery stores / Supermarkets (`supermercados`)
  - Pharmacies (`farmácias`)
  - Gyms (`academias`)
- **Then** the map canvas must instantly render distinctive POI markers for verified businesses matching the selected categories within the active viewport.

### Criterion 2: Public Transit Network Layer
- **Given** a seeker evaluating public transit convenience,
- **When** the seeker activates the "Transporte Público" (Public Transit) layer,
- **Then** the map canvas must render metro lines, train stations, and bus route corridors with standard color-coded route polylines and station glyphs.

### Criterion 3: Walking Distance and Multi-Modal Isochrone Buffers
- **Given** a selected property marker on the map,
- **When** the seeker clicks "Calcular Acessibilidade a Pé" (Calculate Walkability) or selects an amenity category,
- **Then** the Living Map Canvas must compute and draw a pedestrian isochrone polygon (5, 10, or 15-minute walking distance) based on actual street networks per [[con-202609121903]] rather than a crude Euclidean circle.

### Criterion 4: Proximity Distance Metrics on Listing Card
- **Given** properties displayed in the map list view,
- **When** amenity layers are active,
- **Then** each property card must display computed distance badges to the nearest selected amenities (e.g., "Metrô Fradique Coutinho - 4 min a pé", "Supermercado - 250m").

### Criterion 5: Layer Deactivation and Clear View
- **Given** active amenity and transit layers displayed on the canvas,
- **When** the seeker toggles off a category or clicks "Limpar Camadas" (Clear Layers),
- **Then** the corresponding POI markers and isochrone polygons must be immediately removed from the canvas without re-querying property listings.

## Business rules

1. All spatial computations and POI queries must respect tenant privacy boundaries; under `obfuscatedHood: true`, amenity proximity is calculated relative to the neighborhood centroid rather than leaking the secret rooftop coordinates per [[req-202609121913]].
2. Network routing computations must follow verified pedestrian routing graphs (sidewalks, pedestrian crossings) per [[con-202609121903]].
3. Amenity data queries must be cached at the edge to prevent redundant map layer lookups.

---

## Edge cases and errors

- **No Amenities Found in Radius:** If no amenities of a given category exist within a 1,500m pedestrian walking distance, display a subtle badge "Nenhum estabelecimento encontrado em raio de 1.5km" without error dialogs.
- **Routing Engine Latency:** If graph isochrone generation exceeds 1000 ms, render a circular Euclidean approximation labeled "Raio estimado em linha reta".
