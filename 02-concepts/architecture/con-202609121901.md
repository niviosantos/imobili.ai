# Semantic Vector Search and Similarity Retrieval

This note establishes the conceptual architecture of the Imobili.ai search engine, replacing literal keyword indexers with high-dimensional vector representations and hybrid similarity ranking.

---

## Definition

Semantic Vector Search is an information retrieval architecture where unstructured listing descriptions, architectural features, micro-neighborhood traits, and qualitative seeker preferences are mapped into dense mathematical vector spaces (embeddings) of fixed dimension (e.g., 1536 dimensions). Similarity is computed via vector distance metrics combined with an automated Dynamic Irrelevance Floor.

---

## Rationale

Traditional keyword-based search requires exact query-term matches, obscuring highly relevant listings that use synonyms or conceptual descriptions. Dense vector representations preserve semantic context, allowing autonomous agents and human users to search based on complex intent. A dynamic irrelevance floor ensures that anonymous and non-technical seekers do not receive irrelevant listings or require manual threshold tuning.

---

## Rules and constraints

1. **Embedding Model Consistency:** All listings and incoming queries within a tenant partition must be encoded using the same normalized embedding model and dimensionality.
2. **Hybrid Search Execution:** Semantic proximity scoring must be combined with structural SQL filtering (hard constraints such as maximum budget, minimum bedroom count, and zoning).
3. **Dynamic Irrelevance Floor:** Search ranking must apply an automated statistical cutoff: `cutoff = max(0.40, top_score - 0.25)`. If the highest candidate match has a similarity score below 0.40 (`top_score < 0.40`), the search engine returns zero results (`total: 0, items: []`) to prevent algorithmic hallucination and delivery of irrelevant listings.
4. **Deterministic Scoring Threshold:** Vector similarity matches must return an explicit cosine similarity score between 0.0 and 1.0 to enable explainable agent decisions.
5. **Data Isolation Constraint:** Vector collections must adhere to strict tenant boundaries defined in [[req-202609121910]]. Shared vector pools are prohibited.

---

## Examples

1. **Qualitative Intent Query:** A query for *"quiet workspace with tree canopy view and natural afternoon light"* retrieves apartments described as *"serene home office overlooking green boulevard with western exposure"*, achieving a cosine similarity of 0.89 despite zero identical keywords.
2. **Dynamic Floor Filtering:** A query for *"luxury duplex in Jardins"* returns 3 listings scored 0.92, 0.88, and 0.84; a 4th listing scored 0.41 is automatically suppressed by the dynamic irrelevance floor without requiring the user to specify a minimum score parameter.
