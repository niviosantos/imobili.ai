# WebMCP Real Estate Tool and Resource Contracts

This note defines the canonical tool schemas, resource URIs, and prompt abstractions exposed to AI agents via WebMCP.

---

## Definition

WebMCP Real Estate Tool and Resource Contracts are the declarative JSON Schema definitions and URI templates that govern how autonomous agents discover, inspect, and invoke domain-specific capabilities—including hybrid search, spatial calculation, property descriptor retrieval, and transaction negotiation—within an Imobili.ai tenant instance.

---

## Rationale

Without explicit, schema-validated tool and resource contracts, AI copilots and external agents must guess parameter structures and parse unstructured text outputs, leading to tool calling hallucinations and integration failures. Publishing strict JSON Schema contracts (`tools/list`), structured resource URIs (`resources/list`), and validated prompt workflows (`prompts/list`) ensures deterministic interaction, minimizes token context overhead, and enables automated client validation.

---

## Rules and constraints

1. **Canonical Tool Interfaces:** Tenant WebMCP servers must expose the following core real estate tools:
   - `search_properties`: Hybrid semantic and structured filtering tool accepting natural language criteria, price ranges, and property types.
   - `get_property_details`: Granular property inspection tool returning amenities, structural attributes, and media links for a specific property ID.
   - `calculate_commute_isochrone`: Spatial reachability computation tool generating transit and walking polygons per [[con-202609121903]].
   - `submit_offer_intent`: Pre-contractual transaction intent tool requiring verified Tier 2 credentials per [[con-202609121902]] and [[req-202609121911]].
2. **Canonical Resource URI Schemas:** Real estate resources must adhere to deterministic URI schemes:
   - `property://{tenant_id}/listings/{property_id}` - Standardized Markdown and structured JSON property descriptors.
   - `market://{tenant_id}/neighborhoods/{neighborhood_id}` - Neighborhood amenity indexes, transit scores, and polygon geometry.
   - `rules://{tenant_id}/policies/lease-terms` - Declarative rental criteria, deposit rules, and qualification prerequisites.
3. **Strict Parameter Validation:** Tool input parameters must adhere to JSON Schema draft 2020-12 with `additionalProperties: false` to reject unrecognized or ambiguous properties.
4. **Obfuscation at Tool Boundary:** When a tenant enables `obfuscatedHood: true`, `search_properties` and `get_property_details` must suppress street names and exact coordinates, returning only neighborhood centroids unless an authorized viewing booking token is presented per [[req-202609121913]].
5. **No Anonymous Binding Offers:** Tool `submit_offer_intent` must reject unauthenticated Tier 1 calls with HTTP error `AUTH_REQUIRED`. All submitted offers must pass internal brokerage review before binding status is attained.

## Examples

1. **Tool Declaration (`search_properties`):**
```json
{
  "name": "search_properties",
  "description": "Executes hybrid vector and parameterized search across tenant property inventory.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "Natural language lifestyle query" },
      "property_type": { "type": "string", "enum": ["apartment", "house", "penthouse", "commercial"] },
      "price_max": { "type": "number", "description": "Maximum price in local currency" },
      "bedrooms_min": { "type": "integer", "minimum": 0 }
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

2. **Resource Retrieval:** An agent requests `resources/read` with URI `property://alpha/listings/apt-104` and receives verified property attributes, energy efficiency ratings, and sunlight orientation data.
