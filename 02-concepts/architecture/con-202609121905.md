# Web-Native Model Context Protocol (WebMCP) Architecture

WebMCP establishes the web-native Model Context Protocol runtime layer for Imobili.ai.

---

## Definition

The Web-Native Model Context Protocol (WebMCP) is an application-layer architecture and communication standard that exposes tenant property inventories, contextual data, and execution tools to remote AI agents, browser extensions, and LLM copilots using the Model Context Protocol (MCP) delivered over standard web transports (HTTP Server-Sent Events and HTTP POST JSON-RPC).

---

## Rationale

The baseline Model Context Protocol specification was primarily engineered for local process invocation via standard input/output (stdio) pipelines. In decentralized PropTech ecosystems, client agents, browser copilots, and cloud-hosted LLM assistants run outside the host infrastructure and interact over public network boundaries. Traditional web scraping and ad-hoc REST endpoints suffer from high maintenance fragility and token inefficiency. WebMCP provides a standardized, schema-driven interoperability layer directly over HTTP/HTTPS, enabling remote agents to discover capabilities, stream structured listings, and invoke real estate tools with zero local installation overhead.

---

## Rules and constraints

1. **Web-Native Transport Standards:** Tenancy WebMCP endpoints must support HTTP Server-Sent Events (SSE) for server-to-client streaming (`GET /api/v1/mcp/sse`) combined with HTTP POST for client-to-server JSON-RPC 2.0 message dispatch (`POST /api/v1/mcp/messages?sessionId={id}`).
2. **Deterministic Session Management:** Gateway routers must allocate a cryptographically secure `sessionId` upon establishing the SSE transport stream, binding successive POST message dispatches to the active agent session context.
3. **Global CORS and Preflight Policies:** All WebMCP endpoints must declare global CORS headers (`Access-Control-Allow-Origin: *`) and edge preflight caching (`Access-Control-Max-Age: 86400`) per [[con-202609121902]] to allow browser-native agents and extensions direct programmatic access.
4. **Auto-Discovery via Manifests:** WebMCP service availability must be broadcast in `/.well-known/mcp` and documented inside the tenant auto-discovery manifest (`/.well-known/agent.json`) under the `protocols.webmcp` capability stanza.
5. **Strict Tenant Isolation (No Shared Pools):** WebMCP servers operate strictly within isolated tenant database and vector collection boundaries per [[req-202609121910]]. Cross-tenant tool execution or federated MCP indexing is prohibited.
6. **Two-Tier Rate Limit Enforcement:** Inbound WebMCP connections and tool invocations must strictly follow the two-tier throttling architecture defined in [[req-202609121912]] (Tier 1 Public/Anonymous vs. Tier 2 Registered Agent via `X-Agent-Key`), with zero VIP tier bypasses.
7. **Privacy Masking Compliance:** All property listings exposed through WebMCP resources or tool executions must enforce `obfuscatedHood` neighborhood masking per [[req-202609121913]] for unauthenticated or unverified agent sessions.

---

## Examples

1. **Transport Handshake and Discovery:** An external agent establishes an SSE stream via `GET https://alpha.imobili.ai/api/v1/mcp/sse`, receives an assigned `sessionId`, and sends a `tools/list` request via HTTP POST to inspect available tools (`search_properties`, `get_property_details`, `calculate_commute_isochrone`).
2. **Browser Copilot Invocation:** A buyer copilot extension queries `search_properties` with natural language criteria; the WebMCP server executes hybrid vector retrieval and streams back structured property objects without requiring visual HTML parsing.
