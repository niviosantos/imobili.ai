# A2A Agent Card Publication and Validation Runbook

This runbook guides the standardized publication of the auto-discovery manifest (*Agent Card*), enabling external agents to interact via the Agent-Native Protocol (ANP).

---

## Objective

Generate, cryptographically sign, deploy, and validate the `agent.json` auto-discovery manifest with global CORS headers enabled to make tenant real estate capabilities discoverable by browser and server AI agents.

---

## Preconditions

1. Active tenant instance provisioned via [[run-202609121908]].
2. Conceptual alignment with Agent-Native Protocol: [[con-202609121902]].
3. Tenant private signing key available in environment variable `TENANT_PRIVATE_KEY`.
4. Compliance with cryptographic audit requirement [[req-202609121911]] and rate limiting requirement [[req-202609121912]].

---

## Steps

### 1. Generate Canonical Manifest
- **Action:** Create file `agent.json` defining skills and endpoints:
```json
{
  "$schema": "https://imobili.ai/schemas/agent-card-v1.json",
  "name": "Alpha Real Estate Agent",
  "version": "1.0.0",
  "endpoints": {
    "semantic_search": "/api/v1/a2a/search",
    "negotiate": "/api/v1/a2a/negotiate"
  },
  "capabilities": [
    "semantic-vector-search",
    "living-map-polygons",
    "automated-booking"
  ],
  "supported_regions": ["BR-SP-SAOPAULO"]
}
```
- **Expected Result:** File `agent.json` is validated against schema with exit code 0.
- **Failure Handling:** If schema validation fails, correct endpoint keys and rerun schema linter.

### 2. Sign Manifest Cryptographically
- **Action:** Sign the manifest using the tenant private key:
```bash
imobili-cli agent-card sign --file agent.json --key-ref env:TENANT_PRIVATE_KEY --out agent.signed.json
```
- **Expected Result:** Command returns code 0 and outputs signed document `agent.signed.json` containing cryptographic signature headers.
- **Failure Handling:** If signature generation fails, verify that `TENANT_PRIVATE_KEY` contains valid RSA/ED25519 private key material.

### 3. Deploy to Well-Known Path with Global CORS
- **Action:** Deploy the signed manifest to the web server's well-known directory and verify gateway CORS configuration:
```bash
cp agent.signed.json /var/www/html/.well-known/agent.json
```
- **Expected Result:** File `/var/www/html/.well-known/agent.json` exists with file permissions `0644`. Gateway injects `Access-Control-Allow-Origin: *`.
- **Failure Handling:** If copy fails due to permission errors, verify web root ownership and re-execute.

### 4. Execute A2A Discovery and CORS Handshake Test
- **Action:** Run the automated discovery test suite against the live endpoint checking both HTTP response and CORS headers:
```bash
imobili-cli a2a test-discovery --url https://alpha.imobili.ai/.well-known/agent.json --check-cors
```
- **Expected Result:** Process exits with return code 0 and output: `Discovery handshake successful. CORS header Access-Control-Allow-Origin: * validated. All capabilities validated.`
- **Failure Handling:** If handshake fails, inspect HTTP server headers for `Access-Control-Allow-Origin: *` and `Link: </.well-known/agent.json>; rel="service-desc"`.

---

## Verification

1. Fetch manifest over HTTP and verify CORS and Cache headers: `curl -sI https://alpha.imobili.ai/.well-known/agent.json | grep -i "Access-Control-Allow-Origin: \*"` and `curl -sI https://alpha.imobili.ai/.well-known/agent.json | grep -i "Cache-Control: public, max-age=3600"`.
2. Verify preflight caching header: `curl -sI -X OPTIONS https://alpha.imobili.ai/.well-known/agent.json | grep -i "Access-Control-Max-Age: 86400"`.
3. Assert returned name equals `"Alpha Real Estate Agent"`.
4. Verify cryptographic signature via `imobili-cli agent-card verify --file /var/www/html/.well-known/agent.json`.

---

## Rollback

If discovery validation fails:
1. Remove corrupted manifest: `rm -f /var/www/html/.well-known/agent.json`.
2. Disable A2A traffic flag on gateway: `imobili-cli gateway update-feature --tenant imob-alpha-01 --a2a false`.
3. Record publication error in `00-meta/log.md`.
