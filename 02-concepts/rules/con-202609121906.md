# Operational Rules and Agentic Engineering Principles

This document establishes invariant rules for developing, documenting, and operating agents within Imobili.ai.

---

## Definition

Operational Rules and Agentic Engineering Principles define the mandatory engineering constraints, stylistic standards, context budget policies, and public accountability practices governing all code and documentation artifacts in the Imobili.ai project.

---

## Rationale

AI agents operate with bounded token context windows and deterministic parsing engines. Verbose documentation, non-standard linking schemes, and unstated assumptions degrade model reasoning and introduce hallucination risks. Strict operational rules ensure predictable automated execution.

---

## Rules and constraints

1. **Markdown-Native Efficiency:** All specifications, runbooks, and architectural notes must be written in clean, concise Markdown with zero extraneous filler words.
2. **Standard Link Syntax:** All cross-document references must use Obsidian-compatible ID-based wikilinks (syntax: `[[<id>]]`). Positional phrases ("see above") and relative filesystem paths in note prose are prohibited.
3. **Atomic Spec Note Standard:** Every note must address exactly 1 outcome, 1 concept, or 1 procedure, maintaining standalone independence and unambiguous pass/fail criteria.
4. **Public Accountability:** System changes must be recorded in public repositories with reproducible verification steps and traceable decision rationale.
5. **Topological Containment:** Conceptual notes belong strictly in `02-concepts/`, executable procedures belong in `03-runbooks/`, and cross-cutting requirements belong in `04-requirements/`.

---

## Examples

1. **Deterministic Acceptance Criteria:** An acceptance criterion specifies *"HTTP status 200 OK with Content-Type: application/json and maximum response latency of 500 ms"*, providing a clear pass/fail assertion for automated linters.
2. **Explicit Sequence Block:** A note declares its parent task and predecessor story explicitly using `[[tsk-202609131550]]` and `[[sto-202609131605]]`, eliminating reliance on directory file-system order.
