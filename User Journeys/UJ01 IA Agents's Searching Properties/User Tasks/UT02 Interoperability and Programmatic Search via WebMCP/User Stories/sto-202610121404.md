# User Story: Parameterized Property Search Execution via WebMCP

---

## Summary

- **As an** AI agent powering an automated real estate search engine, browser copilot, or AI search assistant,
- **I want to** call the `search_properties` WebMCP tool with structured search filters (natural language query, property type, price ceiling, bedroom count, region, amenities),
- **So that** I receive deterministic, relevance-ranked real estate listings pruned by the dynamic irrelevance floor and sanitized with `obfuscatedHood` privacy masking, formatted for direct consumption by language model agents.

---

## Scope in/out

- **In Scope:** Dispatching `tools/call` JSON-RPC messages for tool `search_properties` to `/api/v1/mcp/messages?sessionId={sessionId}`, validating input parameters against JSON Schema draft 2020-12 (`additionalProperties: false`), hybrid k-NN vector retrieval combined with metadata filtering within isolated tenant collections, applying dynamic irrelevance floor (`cutoff = max(0.40, top_score - 0.25)`), masking exact addresses to neighborhood centroid when `obfuscatedHood: true`, returning canonical URLs and resource URIs (`property://{tenant_id}/listings/{property_id}`), handling zero-match and sub-0.40 absolute floor conditions, and enforcing two-tier rate limiting per [[req-202609121912]].
- **Out of Scope:** Property viewing scheduling, submitting offer intent (handled in separate negotiation tools per [[con-202609121907]]), or multi-tenant listing pooling.

---

## Expected behavior

When an external agent sends a valid `tools/call` request for `search_properties` with valid parameters, the system executes hybrid similarity and metadata queries against the tenant's isolated vector collection, calculates the dynamic irrelevance floor, masks exact addresses if `obfuscatedHood: true`, and returns an MCP-compliant response containing the matching items array and applied cutoff score.

## Acceptance criteria

### Criterion 1: MCP Tool Call Invocation and Dispatch
- **Given** an active WebMCP session with valid `sessionId`,
- **When** the client sends an HTTP POST with a JSON-RPC 2.0 message with method `tools/call`, tool name `search_properties`, and valid arguments to `/api/v1/mcp/messages?sessionId={sessionId}`,
- **Then** the platform must respond with HTTP status `200 OK` (or stream via SSE) and return an MCP tool result object with `isError: false` and `content` containing the structured JSON results array.

### Criterion 2: Strict JSON Schema Parameter Validation
- **Given** an incoming tool call for `search_properties`,
- **When** arguments are validated against the schema defined in [[con-202609121907]],
- **Then** the system must accept `query` (required string), `property_type` (enum: `apartment`, `house`, `penthouse`, `commercial`), `price_max` (number >= 0), `bedrooms_min` (integer >= 0), `region` (string), `amenities` (array of strings), and reject any extraneous properties per `additionalProperties: false` with MCP tool error `isError: true` or JSON-RPC code `-32602` (`Invalid params`).

### Criterion 3: Hybrid Retrieval with Dynamic Irrelevance Floor
- **Given** candidate embeddings and metadata filter results,
- **When** nearest neighbors are evaluated,
- **Then** the search engine must automatically calculate and apply the adaptive dynamic irrelevance floor `cutoff = max(0.40, top_score - 0.25)`, pruning items falling below the threshold distribution knee so agents receive only high-confidence listings without manual threshold configuration.

### Criterion 4: `obfuscatedHood` Privacy Enforcement
- **Given** a tenant instance with `obfuscatedHood: true`,
- **When** property search results are returned to unauthenticated or public Tier 1 agents,
- **Then** each listing item must suppress the street name and building number, providing only the neighborhood name (`region`), neighborhood centroid GPS coordinates, relevance score, and canonical link per [[req-202609121913]].

### Criterion 5: Zero Match and Sub-0.40 Absolute Floor Handling
- **Given** query parameters that yield no database matches or where the highest candidate score falls below the 0.40 minimum floor (`top_score < 0.40`),
- **When** the tool invocation completes,
- **Then** the platform must return success (`isError: false`) with `total: 0`, `items: []`, and `irrelevance_floor_applied: 0.40` without raising an MCP tool error or HTTP failure.

### Criterion 6: Two-Tier Rate Limiting Enforcement
- **Given** incoming `search_properties` tool invocations,
- **When** requests originate from unauthenticated/anonymous clients (Tier 1), the quota is 30 calls per minute per IP; when presenting `X-Agent-Key` (Tier 2), the quota is 120 calls per minute per agent identifier per [[req-202609121912]]. Requests exceeding quotas return HTTP status `429 Too Many Requests`.

## Contracts and data

- **Endpoint:** `POST /api/v1/mcp/messages?sessionId={sessionId}`
- **Request Format:** `application/json` (JSON-RPC 2.0)
- **Example Request:**
```json
{
  "jsonrpc": "2.0",
  "id": "call-001",
  "method": "tools/call",
  "params": {
    "name": "search_properties",
    "arguments": {
      "query": "2 bedroom apartment with balcony near Fradique Coutinho metro",
      "property_type": "apartment",
      "region": "Pinheiros",
      "bedrooms_min": 2,
      "price_max": 5000.00
    }
  }
}
```
- **Example Response (with `obfuscatedHood: true`):**
```json
{
  "jsonrpc": "2.0",
  "id": "call-001",
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\"total\": 1, \"irrelevance_floor_applied\": 0.76, \"items\": [{\"id\": \"prop-sp-042\", \"title\": \"Apartment near Fradique Coutinho Station\", \"region\": \"Pinheiros, Sao Paulo, SP\", \"address\": \"Pinheiros (Exact address masked per tenancy policy)\", \"price\": 4200.00, \"bedrooms\": 2, \"relevance_score\": 0.94, \"canonical_url\": \"https://alpha.imobili.ai/properties/prop-sp-042\", \"resource_uri\": \"property://alpha/listings/prop-sp-042\"}]}"
      }
    ],
    "isError": false
  }
}
```

## Business rules

1. Searches must execute strictly inside the isolated tenant collection mandated by [[req-202609121910]] (No Shared Pools).
2. Two-tier rate limits must be enforced strictly per [[req-202609121912]].
3. LGPD personal data masking and `obfuscatedHood` neighborhood masking must be enforced strictly per [[req-202609121913]].
4. The dynamic irrelevance floor algorithm must be applied by default on all tool queries (`cutoff = max(0.40, top_score - 0.25)`). If the top score is below 0.40, the system must return empty results with `irrelevance_floor_applied: 0.40`.

---

## Edge cases and errors

- **Unknown Tool:** If client requests an unregistered tool name, return JSON-RPC error `-32601` (`Method not found`).
- **Vector Engine Timeout:** If the vector database latency exceeds 1500 ms, return graceful degraded lexical SQL results with header or property `search_mode: fallback-lexical`.
- **Invalid Session:** If `sessionId` is missing, expired, or invalid, return HTTP `404 Not Found` with JSON-RPC error `-32001`.
