# User Story: Broker Calendar Agenda Selection and Appointment Confirmation

---

## Summary

- **As a** property seeker who submitted a visit request,
- **I want to** open a personalized link displaying the assigned broker agent profile and calendar agenda options to select my preferred appointment timeslot,
- **So that** I can secure a confirmed visit directly on the broker's schedule, receive the exact meeting address, and add the event to my personal calendar.

---

## Scope in/out

- **In Scope:** Generating and delivering a secure, signed time-sensitive booking URL (`/visita/agendamento/{token}`) via email/SMS/WhatsApp, rendering the assigned licensed broker agent profile (photo, full name, official CRECI license number, rating), displaying an interactive calendar grid with real-time available timeslots, atomic timeslot selection and double-booking conflict locking, transitioning visit status to `CONFIRMED`, unmasking the exact rooftop street address upon confirmed booking per [[req-202609121913]], and dispatching standard calendar (.ics) invites.
- **Out of Scope:** In-person biometric identity verification at the building entrance and signing lease agreements.

---

## Preconditions

1. Visit request submitted per [[sto-202610121710]].
2. Broker agent assigned with synchronized calendar availability.
3. Cryptographic token generator configured with a 48-hour expiration TTL.

---

## Expected behavior

The seeker receives a personalized booking link and opens the scheduling view. The page presents the assigned broker's credentials (CRECI license) and available calendar slots. The seeker clicks a desired day and time, and clicks "Confirmar Visita". The platform locks the slot, creates the calendar event, unmasks the exact address with GPS navigation links (Google Maps / Waze), and sends a confirmation email and SMS with the attached calendar file.

---

## Acceptance criteria

### Criterion 1: Secure Personalized Agenda Link Delivery
- **Given** an approved visit request,
- **When** the agency broker assignment completes,
- **Then** the platform must generate a signed booking token link (`/visita/agendamento/{token}`) with 48-hour validity and deliver it via email and SMS to the seeker.

### Criterion 2: Assigned Broker Profile Presentation
- **Given** the seeker opening the booking link in a browser,
- **When** the agenda page loads,
- **Then** the interface must clearly display the assigned broker agent's:
  - Professional photograph
  - Full name
  - Official state CRECI registration number (e.g., `CRECI 123456-F / SP`)
  - Agency affiliation and direct WhatsApp contact link

### Criterion 3: Real-Time Calendar Slot Selection
- **Given** the active booking view,
- **When** the seeker inspects available dates over the next 14 business days,
- **Then** the system must render an interactive calendar displaying only available, non-conflicting time slots (e.g., 09:30, 11:00, 14:30, 16:00).

### Criterion 4: Atomic Slot Locking and Confirmation
- **Given** a seeker choosing a specific timeslot,
- **When** the seeker clicks "Confirmar Agendamento",
- **Then** the platform must atomically acquire a lock on the selected slot, transition the record status to `CONFIRMED`, and prevent duplicate bookings for that broker and property window.

### Criterion 5: Post-Confirmation Address Unmasking
- **Given** a tenant configured with `obfuscatedHood: true`,
- **When** the appointment is locked and confirmed,
- **Then** the platform must unmask the exact property address (street name, building number, apartment/block, postal code CEP) and provide direct navigation links (Google Maps, Waze) per [[req-202609121913]].

### Criterion 6: Calendar Invite (.ics) Dispatch
- **Given** a successfully confirmed booking,
- **When** the confirmation event fires,
- **Then** the system must dispatch a confirmation email containing a downloadable iCalendar (`.ics`) file with the exact date, time, broker name, and meeting address.

## Business rules

1. All booking transitions must be recorded sequentially in the tenant immutable audit log per [[req-202609121911]].
2. Address unmasking is permitted strictly after explicit confirmation of the visit appointment per [[req-202609121913]].
3. Concurrent bookings for the same timeslot must resolve via database optimistic concurrency locking; second applicant receives clear notification to select another slot.

---

## Edge cases and errors

- **Expired Token:** If the booking link is accessed after 48 hours, return status with option to "Gerar novo link de agendamento".
- **Slot Booked in Parallel:** If another user confirms the exact timeslot milliseconds earlier, return HTTP 409 Conflict with immediate refresh of available slots.
