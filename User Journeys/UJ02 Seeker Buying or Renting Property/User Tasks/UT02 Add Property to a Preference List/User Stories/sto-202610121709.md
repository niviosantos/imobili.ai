# User Story: Favorite Preference List Management

---

## Summary

- **As an** authenticated property seeker,
- **I want to** add and remove candidate properties to and from my personal preference list,
- **So that** I can maintain a curated collection of favorite properties, monitor price or availability updates, and compare listings before scheduling visits.

---

## Scope in/out

- **In Scope:** One-click favorite toggle (heart/bookmark icon) across map cards, search results, and property detail views, adding a property to the user's preference list, removing a property from the preference list, dedicated "Meus Favoritos" (My Preferences) page listing all saved properties with current prices and status badges, persistent synchronization across sessions, and optimistic UI updates.
- **Out of Scope:** Exporting PDF dossiers and scheduling physical visits (handled in [[sto-202610121710]]).

---

## Preconditions

1. Seeker authenticated via guest account or social credentials per [[sto-202610121708]].
2. Tenant user preferences database partition operational per [[req-202609121910]].
3. Property listings published and accessible.

---

## Expected behavior

When a seeker clicks the heart icon on any property card or detail view, the platform toggles the item's favorite state, updates the persistent preference list in the database, and provides immediate visual feedback. Navigating to the "Meus Favoritos" view presents all curated properties with direct shortcuts to schedule visits or chat with brokers.

---

## Acceptance criteria

### Criterion 1: Instant Favorite Toggle Action
- **Given** a property seeker viewing listings on the map canvas, search results feed, or property detail page,
- **When** the seeker clicks the heart/favorite icon on an unbookmarked property,
- **Then** the platform must immediately render the icon in an active filled state, dispatch an addition request to `/api/v1/user/favorites`, and display a subtle confirmation toast ("Imóvel adicionado aos favoritos").

### Criterion 2: Removal from Preference List
- **Given** a property currently present in the seeker's preference list,
- **When** the seeker clicks the active heart icon on the property card or clicks "Remover" in the favorites list,
- **Then** the platform must dispatch a removal request to `/api/v1/user/favorites/{property_id}`, remove the item from the list view, and update the total favorites counter.

### Criterion 3: Dedicated Preference List View
- **Given** an authenticated seeker with saved properties,
- **When** the seeker navigates to the "Meus Favoritos" page (`/favoritos`),
- **Then** the platform must display all saved listings with current price, status (Disponível / Reservado), bedroom configuration, neighborhood, and a direct "Agendar Visita" action button.

### Criterion 4: Multi-Device Persistence
- **Given** a seeker who added favorites on a mobile browser using Google login,
- **When** the seeker subsequently logs into the tenant web portal on a desktop workstation with the same account,
- **Then** the preference list must immediately reflect all previously saved properties without loss.

### Criterion 5: Optimistic UI with Error Rollback
- **Given** a seeker toggling a favorite icon,
- **When** a network connectivity failure prevents the backend API call from succeeding,
- **Then** the interface must revert the heart icon to its previous state and show a clear error notification ("Não foi possível salvar o imóvel. Verifique sua conexão.").

---

## Contracts and data

- **Endpoints:**
  - `GET /api/v1/user/favorites` - Retrieve all saved properties
  - `POST /api/v1/user/favorites` - Add property. Payload: `{ "property_id": "prop-sp-042" }`
  - `DELETE /api/v1/user/favorites/{property_id}` - Remove property
- **Example Favorites Response Payload:**
```json
{
  "total": 2,
  "items": [
    {
      "property_id": "prop-sp-042",
      "title": "Apartamento em Pinheiros com Varanda Gourmet",
      "price": 850000.00,
      "bedrooms": 2,
      "suites": 1,
      "region": "Pinheiros, Sao Paulo",
      "status": "available",
      "saved_at": "2026-10-12T17:09:00Z",
      "thumbnail_url": "https://cdn.imobili.ai/photos/prop-sp-042/thumb.jpg"
    }
  ]
}
```

---

## Business rules

1. Preference lists must be stored strictly within the tenant database boundary per [[req-202609121910]]; cross-brokerage favorite sharing is prohibited.
2. The system must notify the seeker if a saved property changes price or becomes reserved/rented.
3. Seeker interaction logs must be securely appended per [[req-202609121911]].

---

## Edge cases and errors

- **Deleted or Delisted Property:** If a saved property is delisted or sold by the agency, display a status badge "Imóvel indisponível" with option to remove or view similar properties.
- **Empty Favorites State:** When zero properties are saved, display an inviting empty state illustration with a button "Explorar Imóveis no Mapa".
