# User Story: WebMCP Capability Discovery and Session Negotiation

---

## Summary

- **As an** AI agent powering an automated real estate search engine, browser copilot, or web crawler (such as Googlebot or AI search indexers),
- **I want to** identify the tenant's WebMCP service through standard well-known endpoints (`/.well-known/mcp`), HTTP `Link` headers, HTML `<link>` discovery tags, and Schema.org JSON-LD structured data with global CORS enabled,
- **So that** I can establish a WebMCP Server-Sent Events (SSE) session (`/api/v1/mcp/sse`), receive an assigned session ID, inspect available tools via `tools/list`, and confirm programmatic real estate search capabilities without human intervention.

---

## Scope in/out

- **In Scope:** Serving `/.well-known/mcp` manifest with HTTP status 200 OK, injecting HTTP `Link` headers (`rel="service-desc"` and `rel="mcp-server"`) on root domain responses (`GET /`), injecting HTML `<head>` link tags and Schema.org JSON-LD structured data for web search engines like Google, publishing explicit crawler permissions in `robots.txt`, serving global CORS headers (`Access-Control-Allow-Origin: *`) across discovery and transport endpoints, CORS preflight `OPTIONS` handling with edge caching (`Access-Control-Max-Age: 86400`), manifest caching (`Cache-Control: public, max-age=3600`), SSE session initiation (`GET /api/v1/mcp/sse`) assigning cryptographically secure `sessionId`, and MCP tool catalog inspection (`tools/list`) declaring `search_properties`.
- **Out of Scope:** Executing property vector searches (handled in [[sto-202610121404]]), lease contract signing, or financial deposit processing.

---

## Preconditions

1. Tenant instance provisioned and active per [[run-202609121908]].
2. WebMCP runtime architecture operational per [[con-202609121905]].
3. WebMCP real estate tool contracts published per [[con-202609121907]].
4. Gateway routing, TLS termination, and rate limiting operational per [[req-202609121912]].

## Expected behavior

When an external agent or web search engine queries `/.well-known/mcp` or requests the homepage (`GET /`), the platform returns the machine-readable WebMCP manifest, HTTP `Link` headers, HTML metadata, and JSON-LD structured data with global CORS headers. When an agent opens an SSE connection to `/api/v1/mcp/sse`, the gateway allocates an ephemeral session ID, transmits the messages endpoint URI via an initial SSE event, and allows the client to initialize and list available tools via `tools/list`.

---

## Acceptance criteria

### Criterion 1: Well-Known Manifest (`/.well-known/mcp`), Global CORS, and Edge Caching
- **Given** an external AI agent, browser extension, or search engine crawler,
- **When** the client sends a `GET /.well-known/mcp` request,
- **Then** the platform must respond with HTTP status `200 OK`, header `Content-Type: application/json`, header `Access-Control-Allow-Origin: *`, header `Cache-Control: public, max-age=3600`, and a JSON manifest declaring server name, MCP protocol version `2024-11-05`, transport endpoint `/api/v1/mcp/sse`, and capabilities (`tools`, `resources`).

### Criterion 2: CORS Preflight Support and Preflight Caching
- **Given** a cross-origin client initiating an HTTP preflight check,
- **When** the client sends an `OPTIONS /.well-known/mcp` or `OPTIONS /api/v1/mcp/sse` request,
- **Then** the platform must respond with HTTP status `204 No Content` and headers `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Max-Age: 86400`.

### Criterion 3: Search Engine Discovery via HTTP Link Header and HTML Metadata
- **Given** an external client or web search engine (such as Googlebot or an AI crawler) querying the tenant domain root (`GET /`),
- **When** the root response is received,
- **Then** the response must include:
  1. HTTP header `Link: </.well-known/mcp>; rel="service-desc"; type="application/json", </api/v1/mcp/sse>; rel="mcp-server"; type="text/event-stream"`.
  2. HTML `<head>` tag `<link rel="mcp-server" href="/api/v1/mcp/sse" type="text/event-stream" title="Imobili.ai WebMCP Server">`.
  3. HTML `<head>` Schema.org JSON-LD snippet declaring `@type: RealEstateAgent` with a `potentialAction` of `@type: SearchAction` targeting the WebMCP endpoint.
  4. Verification that `robots.txt` explicitly allows crawling of `/.well-known/mcp` via directive `Allow: /.well-known/mcp`.

### Criterion 4: SSE Transport Handshake and Session Allocation
- **Given** an agent connecting to the streaming endpoint,
- **When** the client sends a `GET /api/v1/mcp/sse` request with header `Accept: text/event-stream`,
- **Then** the platform must respond with HTTP status `200 OK`, header `Content-Type: text/event-stream`, header `Access-Control-Allow-Origin: *`, and stream an initial SSE event `endpoint` with payload pointing to `/api/v1/mcp/messages?sessionId={sessionId}` where `sessionId` is a 128-bit cryptographically secure hex string.

### Criterion 5: Tools Catalog Inspection (`tools/list`)
- **Given** an established WebMCP session,
- **When** the client posts a JSON-RPC 2.0 message with method `tools/list` to `/api/v1/mcp/messages?sessionId={sessionId}`,
- **Then** the platform must respond with HTTP status `200 OK` (or stream via SSE) declaring tool `search_properties` with JSON Schema input parameters matching [[con-202609121907]].

### Criterion 6: Abuse Prevention Quarantine
- **Given** an incoming client IP address,
- **When** the client exceeds 120 requests per minute targeting discovery or SSE endpoints,
- **Then** the platform must return HTTP status `429 Too Many Requests` followed by a temporary 24-hour quarantine per [[req-202609121912]].

## Contracts and data

- **Discovery Endpoint:** `GET /.well-known/mcp`
- **SSE Transport Endpoint:** `GET /api/v1/mcp/sse`
- **Messages Endpoint Template:** `POST /api/v1/mcp/messages?sessionId={sessionId}`
- **CORS Headers:** `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, `Access-Control-Max-Age: 86400`
- **Cache Header:** `Cache-Control: public, max-age=3600`
- **Example Discovery Manifest (`/.well-known/mcp`):**

  "version": "1.0.0",

  "transport": {
    "type": "sse",

## Business rules

1. The manifest and discovery endpoints must be publicly accessible without requiring client authentication cookies, bearer tokens, or interactive CAPTCHAs.
2. Global CORS headers (`Access-Control-Allow-Origin: *`) must be emitted unconditionally on discovery, SSE, and messages paths to permit zero-friction consumption by browser-based AI extensions and external agent clouds.
3. Tenant isolation boundaries must be enforced strictly per [[req-202609121910]] (No Shared Pools).
4. Inbound connections must comply with rate limiting quotas defined in [[req-202609121912]] (Tier 1 Public/Anonymous: max 60 req/min on discovery, 30 req/min on execution; Tier 2 Registered Agent via `X-Agent-Key`: max 120 req/min).
5. Ephemeral session state must expire after 15 minutes of inactivity per [[con-202609121905]], releasing gateway memory caches.
6. Discovery responses must enforce `Cache-Control: public, max-age=3600` (manifest) and `Access-Control-Max-Age: 86400` (preflight OPTIONS) to optimize CDN edge delivery.

---

## Edge cases and errors

- **Missing Manifest:** If the manifest file is corrupt or unconfigured, return HTTP `503 Service Unavailable` with error `WEBMCP_SERVICE_UNAVAILABLE`.
- **Invalid Session ID:** If a message POST specifies an expired or invalid `sessionId`, return HTTP `404 Not Found` with JSON-RPC error `-32001` (`Session expired or not found`).
- **Disallowed Methods:** If client issues unsupported HTTP verbs (`PUT`, `DELETE`) to `/api/v1/mcp/sse`, return HTTP `405 Method Not Allowed`.

## Verification plan

- **Test 1 (Manifest Discovery):** Execute `curl -sSf -i https://alpha.imobili.ai/.well-known/mcp`. Verify exit code 0, `Content-Type: application/json`, presence of `Access-Control-Allow-Origin: *`, and `Cache-Control: public, max-age=3600`.
- **Test 2 (Preflight Check):** Execute `curl -sI -X OPTIONS https://alpha.imobili.ai/.well-known/mcp`. Verify HTTP `204 No Content`, `Access-Control-Allow-Methods: GET, POST, OPTIONS`, and `Access-Control-Max-Age: 86400`.
- **Test 3 (Search Engine Signals):** Execute `curl -sI https://alpha.imobili.ai/ | grep -i "Link:"`. Verify presence of `rel="mcp-server"`. Execute `curl -s https://alpha.imobili.ai/ | grep -i "rel=\"mcp-server\""`. Verify HTML link tag presence.
- **Test 4 (SSE Handshake):** Execute `curl -N -H "Accept: text/event-stream" https://alpha.imobili.ai/api/v1/mcp/sse`. Verify initial event `endpoint` contains `sessionId`.
- **Test 5 (Rate Limit Check):** Dispatch 65 rapid requests to `/.well-known/mcp` from a single IP and assert HTTP `429 Too Many Requests`.
