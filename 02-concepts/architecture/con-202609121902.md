# Agent-Native Protocol (ANP)

The Agent-Native Protocol (ANP) defines the direct Agent-to-Agent (A2A) communication layer for Imobili.ai.

---

## Definition

The Agent-Native Protocol (ANP) is an application-level communication standard based on HTTP, JSON-RPC, and declarative manifests that enables autonomous AI software agents to discover capabilities, execute parameterized property queries, inspect contractual constraints, and submit verified transaction proposals without requiring human visual interfaces.

---

## Rationale

Autonomous AI agents cannot reliably navigate brittle web layouts, fluctuating CSS classes, or interactive CAPTCHAs designed for human eyes. ANP establishes a deterministic, machine-first communication channel that optimizes token context consumption, enforces schema validation, and enables real-time agentic interactions.

---

## Rules and constraints

1. **Standardized Auto-Discovery:** Every participating tenant must publish an `agent.json` manifest at `/.well-known/agent.json` and declare it via standard HTTP `Link` headers.
2. **Global CORS & Edge Caching on Discovery:** All discovery endpoints must enable global CORS headers (`Access-Control-Allow-Origin: *`), preflight caching (`Access-Control-Max-Age: 86400`), and manifest edge caching (`Cache-Control: public, max-age=3600`) to ensure browser-native AI agents and extensions can discover capabilities with minimal latency and origin load.
3. **Account Requirement for Offers:** Transactional and counterproposal endpoints require an authenticated user account with verified registration. Anonymous offers are strictly prohibited.
4. **Internal Agency Validation Workflow:** Every incoming offer or negotiation proposal must pass through an internal brokerage validation workflow before binding legal commitments, preventing bot-generated spam and unauthorized bids.
5. **Rate Limiting Policy:** Endpoints must implement two-tier throttling (Public/Anonymous vs. Registered Agent) without VIP tiers per [[req-202609121912]]. Registered agent credentials remain active indefinitely until administrative revocation (permanent credential model).
6. **Asynchronous Status Polling Model:** Because internal brokerage review is an asynchronous process, transaction workflows expose dedicated status endpoints (`GET /api/v1/a2a/offers/{offer_id}`) allowing client agents to poll lifecycle transitions (`PENDING_AGENCY_VALIDATION`, `ACCEPTED`, `REJECTED`, `EXPIRED`) without requiring external webhook infrastructure.

---

## Examples

1. **Auto-Discovery Resolution:** An external AI browser queries `GET /.well-known/agent.json` and parses supported search capabilities (`semantic-vector-search`, `living-map-polygons`), service endpoints, and cryptographic signing public keys.
2. **Deterministic Query Dispatch:** An agent submits a structured JSON-RPC payload invoking `search_properties` with explicit parameters (`property_type: "apartment"`, `bedrooms_min: 2`) and receives a validated JSON list of matching property objects.
