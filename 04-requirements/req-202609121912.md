# A2A Rate Limiting and Service Protection

This requirement defines the automated throttling, IP quarantine, and anti-abuse policies protecting public discovery and search endpoints against denial-of-service and predatory scraping attacks.

---

## Statement

The platform must enforce deterministic, two-tiered rate limits across all public HTTP and JSON-RPC endpoints: Tier 1 for Public/Anonymous clients (unauthenticated, tracked by client IP) and Tier 2 for Registered Agents (authenticated via `X-Agent-Key` or basic cryptographic signature header). The platform explicitly excludes any third VIP or customized enterprise tier. Requests exceeding tier quotas must return HTTP `429 Too Many Requests`. Excessive abuse by anonymous clients (> 120 requests/minute) must trigger an automated 24-hour IP quarantine, whereas registered agents receive soft throttling without IP bans.

---

## Rationale

Because Imobili.ai exposes public auto-discovery manifests and programmatic vector search APIs to external autonomous agents, unprotected gateways face high risks of resource exhaustion, vector compute denial-of-service, and malicious mass-scraping by competitors. A clean two-tier model balances open, zero-friction discovery for prospective agents with operational reliability for verified agencies, eliminating the governance overhead and complex mTLS infrastructure of bespoke VIP partner tiers.

## Measurable acceptance criteria

1. **Tier 1 (Public / Anonymous) Throttling:** Requests without authentication credentials (`X-Agent-Key` or `X-Agent-Signature`) must be rate-limited per client IP address to a maximum of 60 requests per minute on discovery endpoints (`/.well-known/agent-card.json`) and 30 requests per minute on search endpoints (`/api/v1/a2a/search`).
2. **Tier 2 (Registered Agent) Throttling:** Requests providing a valid API key header (`X-Agent-Key`) or basic signature header (`X-Agent-Signature`) must be rate-limited per registered agent identifier to a maximum of 120 requests per minute across all endpoints.
3. **Exclusion of VIP Tier:** The system must enforce Tier 2 as the maximum permissible rate limit. No third tier, custom partner quota, or bypass certificate may be configured.
4. **Tier 1 Abuse Quarantine:** Anonymous client IP addresses exceeding 120 requests per minute on any endpoint must trigger an automated temporary block lasting exactly 24 hours (86,400 seconds), returning HTTP status `403 Forbidden` with header `X-Quarantine-Until`.
5. **Tier 2 Soft Throttle:** Registered agents exceeding 120 requests per minute must receive HTTP status `429 Too Many Requests` with header `Retry-After: 60`, without triggering an IP quarantine ban.
6. **Standard Header Specification:** All rate-limited responses must return standard rate-limiting headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `Retry-After`.
7. **Key Lifecycle Invariant (Permanent until Revocation):** Tier 2 API keys (`X-Agent-Key`) remain active indefinitely without automated calendar-based expiration. Keys are invalidated exclusively via explicit administrative revocation (OpenAI/Stripe credential model), preventing uncoordinated production downtime for autonomous agent clients.

## Verification

1. **Verify Tier 1 Quota:** Dispatch 35 unauthenticated search requests within 60 seconds from a single IP address. Assert requests 31 through 35 return HTTP status `429 Too Many Requests`.
2. **Verify Tier 1 Quarantine:** Dispatch 125 unauthenticated requests within 60 seconds from a single IP address. Assert requests 121 and above return HTTP status `403 Forbidden` with header `X-Quarantine-Until` indicating 24 hours duration.
3. **Verify Tier 2 Quota:** Dispatch 100 search requests within 60 seconds presenting header `X-Agent-Key: valid-test-key`. Assert 100% of requests return HTTP status `200 OK`.
4. **Verify Tier 2 Soft Throttle:** Dispatch 125 search requests within 60 seconds presenting header `X-Agent-Key: valid-test-key`. Assert requests 121 through 125 return HTTP status `429 Too Many Requests` with header `Retry-After: 60` and assert that the client IP address remains unbanned.
5. **Verify Manual Revocation:** Invoke administrative revocation on `valid-test-key`; subsequent requests presenting the key must immediately return HTTP status `401 Unauthorized`.
