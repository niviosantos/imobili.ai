# Living Map Canvas: Dynamic Cartography as an Operating System

The Living Map Canvas transforms the map from a decorative visual element into an interactive geospatial operating system for agents and human users.

---

## Definition

The Living Map Canvas is a continuous, computable geospatial runtime surface that accepts multi-criteria spatial constraints (transit isochrones, pedestrian paths, amenities, urban zoning) and computes analytical geometric layers (GeoJSON polygons, Voronoi partitions, density heatmaps) directly consumable by AI reasoning engines, with native support for tenant-level neighborhood privacy masking (`obfuscatedHood`).

---

## Rationale

Traditional real estate portals display maps merely as passive grids of static coordinates with click-to-view popups. AI agents require geometric surfaces they can manipulate algebraically—such as intersecting transit commute time polygons with school catchment boundaries—to evaluate location suitability objectively while preserving homeowner privacy per agency policy.

---

## Rules and constraints

1. **Geometry-In / Geometry-Out Interface:** Spatial query endpoints must accept geometric boundaries (GeoJSON polygons) as input filters and output computed spatial data structures.
2. **Multi-Modal Transit Isochrones:** Commute calculations must calculate realistic multimodal travel times (pedestrian walking, cycling, rail transit, vehicular driving) based on physical routing networks rather than Euclidean radius circles.
3. **Amenity Proximity Computation:** Neighborhood amenity scores must be computed dynamically using pedestrian network distance to verified amenities (schools, bakeries, grocery stores, pharmacies).
4. **Tenant `obfuscatedHood` Privacy Policy:** If a tenant enables the `obfuscatedHood: true` configuration, property map pins and coordinates must be obfuscated to the centroid polygon of the containing neighborhood until an in-person viewing is verified per [[req-202609121913]]. Authenticated internal tenant personnel (brokers, managers, admins) maintain total bypass to view plaintext addresses and exact rooftop coordinates across all internal administrative interfaces.
5. **Tenant Spatial Isolation:** Spatial listing queries must respect multi-tenant database partitions defined in [[req-202609121910]].

---

## Examples

1. **15-Minute Transit Polygon Computation:** An agent requests a 15-minute walking isochrone around a central subway station; the Living Map Canvas computes a GeoJSON polygon factoring in pedestrian crosswalks and topographic contours.
2. **Obfuscated Neighborhood Rendering:** Under `obfuscatedHood: true`, a search returns a listing rendered within a shaded neighborhood boundary (e.g., Pinheiros centroid) without revealing the specific street address or exact rooftop coordinates.
