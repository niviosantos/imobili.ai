# User Story: Visit Request Initiation and Property Viewing Dispatch

---

## Summary

- **As a** property seeker interested in purchasing or renting a specific property,
- **I want to** submit a formal visit request specifying my preferred dates and time windows,
- **So that** the brokerage can assign an authorized broker agent and generate a calendar scheduling link for me.

---

## Scope in/out

- **In Scope:** Interactive "Agendar Visita" (Schedule Visit) modal on property detail and favorites views, inputting preferred days of the week and time shifts (morning, afternoon, weekend), capturing seeker contact details (name, email, phone/WhatsApp) or reusing authenticated profile data, validating property availability, creating a visit dispatch record in the tenant database, and triggering an automated notification dispatch.
- **Out of Scope:** Selecting specific calendar timeslots from the broker agenda (handled in [[sto-202610121711]]) and WhatsApp deep linking (handled in [[sto-202610121712]]).

---

## Preconditions

1. Target property record is active and available for viewings.
2. Seeker identity verified via guest account or contact form submission.
3. Agency routing rules active to assign responsible licensed brokers.

---

## Expected behavior

When a seeker clicks "Agendar Visita" on a listing, a scheduling request dialog opens. The seeker specifies their preferred availability periods and confirms contact information. Upon submission, the platform registers the visit request in status `AGENDA_LINK_PENDING`, triggers the agency broker assignment workflow, and displays an immediate confirmation with instructions that a personalized scheduling link is on its way.

---

## Acceptance criteria

### Criterion 1: Visit Request Dialog Trigger
- **Given** a property seeker viewing a listing on the detail page or favorites list,
- **When** the seeker clicks "Agendar Visita",
- **Then** the platform must open a visit request dialog pre-populated with the property ID, title, and seeker's authenticated name and email (if logged in).

### Criterion 2: Preferred Time Windows Selection
- **Given** the visit request form,
- **When** the seeker configures their availability,
- **Then** the form must allow selecting preferred day ranges (e.g., "Próximos 3 dias", "Fim de semana") and preferred shifts ("Manhã - 09h às 12h", "Tarde - 13h às 18h", "Qualquer horário").

### Criterion 3: Contact Information Validation
- **Given** an unauthenticated or guest seeker,
- **When** submitting the visit request,
- **Then** the platform must require and validate a valid Brazilian phone/WhatsApp number (11 digits with DDD) and email address before proceeding.

### Criterion 4: Dispatch Record Creation and State Assignment
- **Given** a validly completed visit form,
- **When** the seeker clicks "Confirmar Solicitação",
- **Then** the system must create an immutable visit record with status `PENDING_BROKER_ASSIGNMENT`, associate the property ID, log the submission timestamp, and trigger the broker allocation engine.

### Criterion 5: Privacy Preservation Prior to Confirmation
- **Given** a tenant configured with `obfuscatedHood: true`,
- **When** the visit request is submitted,
- **Then** the platform must maintain the property's exact address masked in the confirmation dialog, clarifying that full rooftop directions will be delivered once the specific timeslot is locked per [[req-202609121913]].

## Contracts and data

- **Endpoint:** `POST /api/v1/visits/request`
- **Request Payload:**
```json
{
  "property_id": "prop-sp-042",
  "seeker": {
    "name": "Maria Silva",
    "email": "maria.silva@example.com",

  "preferred_shifts": ["morning", "afternoon"],
  "preferred_days": ["weekdays"],

  "notes": "Tenho interesse em conhecer as areas comuns do condominio."

```
- **Example Response Payload:**
```json
{

```

## Business rules

1. All visit requests must be logged sequentially with SHA-256 audit chaining per [[req-202609121911]].
2. Requests must execute strictly inside the tenant isolation boundary per [[req-202609121910]].
3. Exact street addresses must remain masked until the appointment is confirmed by the broker per [[req-202609121913]].

---

## Edge cases and errors

- **Property Temporarily Unavailable:** If property viewing is suspended (e.g., owner traveling), return status with message offering notification when viewings resume.
- **Repeated Submissions:** Submitting multiple requests for the same property within 10 minutes returns the existing active `request_id` idempotently.
