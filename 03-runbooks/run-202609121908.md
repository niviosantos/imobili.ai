# Self-Service Multi-Tenant Deployment Runbook

This runbook guides executor agents and human operators through the deterministic instantiation of a new tenant within the Imobili.ai ecosystem.

---

## Objective

Provision an isolated multi-tenant environment for a real estate agency, initializing segregated vector database collections, routing domains, and TLS certificates in under 300 seconds.

---

## Preconditions

1. Administrative credentials and CLI access to the target cluster environment.
2. Conceptual alignment with multi-tenant architecture: [[con-202609121904]].
3. Verification that tenant identifiers conform to lowercase alphanumeric syntax (e.g., `imob-alpha-01`).
4. Compliance with multi-tenant isolation requirement (no shared pools): [[req-202609121910]].

---

## Steps

### 1. Define Declarative Tenant Manifest
- **Action:** Create file `tenant-alpha.yaml` with the following definition:
```yaml
tenant:
  id: "imob-alpha-01"
  name: "Alpha Realty"
  domain: "alpha.imobili.ai"
  isolation_level: "namespace-isolated"
  storage:
    vector_db_collection: "imob_alpha_vectors"
    encryption_key_ref: "vault://keys/imob-alpha-01"
```
- **Expected Result:** File `tenant-alpha.yaml` is saved with UTF-8 encoding and valid YAML syntax.
- **Failure Handling:** If YAML syntax validation fails, reformat indentation and re-validate before proceeding.

### 2. Initialize Vector Indexes
- **Action:** Execute the provisioning command for the isolated vector collection:
```bash
imobili-cli tenant provision --config tenant-alpha.yaml --init-vectors
```
- **Expected Result:** Command returns code 0 with output: `Status: 200 OK | Collection imob_alpha_vectors created with dimension 1536.`
- **Failure Handling:** If the collection already exists or storage fails, verify Vault key reference and rerun with `--force-retry`.

### 3. Bind Domain Routing and TLS
- **Action:** Bind the tenant domain to the gateway TLS proxy:
```bash
imobili-cli gateway bind --tenant imob-alpha-01 --domain alpha.imobili.ai
```
- **Expected Result:** Command returns code 0 with output: `Status: 200 OK | Domain alpha.imobili.ai bound to gateway.`
- **Failure Handling:** If DNS resolution fails, verify CNAME propagation using `dig alpha.imobili.ai +short`.

### 4. Execute Sanity and Healthcheck Verification
- **Action:** Perform health check against the provisioned endpoint:
```bash
curl -f https://alpha.imobili.ai/healthz
```
- **Expected Result:** HTTP status 200 OK with payload:
```json
{ "status": "healthy", "tenant": "imob-alpha-01", "a2a_ready": true }
```
- **Failure Handling:** If status is non-200, inspect gateway logs via `imobili-cli logs --tenant imob-alpha-01` and execute rollback if health remains degraded after 3 retries.

---

## Verification

1. Verify vector collection creation via `imobili-cli vectors list | grep imob_alpha_vectors`.
2. Verify TLS certificate expiration date via `curl -Iv https://alpha.imobili.ai 2>&1 | grep "expire date"`.
3. Assert that healthcheck returns HTTP status 200 with `a2a_ready: true`.

---

## Rollback

If provisioning fails at any step:
1. Run `imobili-cli tenant teardown --tenant imob-alpha-01 --purge-failed`.
2. Run `imobili-cli gateway unbind --domain alpha.imobili.ai`.
3. Record failure details in the audit log.
