# Data Privacy and LGPD Compliance

This requirement defines the statutory personal data protection principles applicable across property listings, agent negotiations, and programmatic queries, conforming to the Brazilian General Data Protection Law (LGPD - Law 13.709/2018).

---

## Statement

The platform must prohibit the storage, exposure, or vector indexing of unmasked Personally Identifiable Information (PII)—including property owner names, tax identification numbers (CPF/CNPJ), phone numbers, and private tenancy contracts—across public endpoints and external agent query responses. Furthermore, the platform must provide an `obfuscatedHood` tenancy configuration parameter that agencies can activate to mask exact street addresses and GPS coordinates to the containing neighborhood centroid until an in-person viewing is confirmed by an authenticated seeker.

---

## Rationale

Real estate advertising requires granular property descriptors (neighborhood, amenities, geometric dimensions) without compromising homeowner privacy or exposing tenants to physical security vulnerabilities, stalking, or unlawful commercial profiling under LGPD legislation. The tenant-configurable `obfuscatedHood` parameter empowers brokerages to protect exclusive property listings from unauthorized direct scouting while maintaining high discoverability.

## Measurable acceptance criteria

1. **PII Filtering at Ingestion:** Property ingestion pipelines must reject or automatically scrub any raw listing text containing CPF, CNPJ, or personal phone number patterns.
2. **`obfuscatedHood` Tenancy Configuration:** Every tenant configuration must support the boolean property `obfuscatedHood` (default: `true`).
3. **Address Obfuscation Behavior:** When `obfuscatedHood` is `true`, public search endpoints (`/api/v1/a2a/search`) must suppress the street name, house/building number, and exact lat/long coordinates, returning only the neighborhood name and neighborhood centroid polygon.
4. **Viewing De-obfuscation Exception:** Exact address and property coordinates may only be revealed to a seeker agent if the request presents an authenticated account token tied to a confirmed viewing appointment with state `VIEWING_CONFIRMED`.
5. **Data Subject Rights:** Tenants and owners must have an automated programmatic capability to request data anonymization or deletion within 72 hours of verification.
6. **Audit Log Anonymization:** System query logs must store hashed IP addresses (SHA-256 with salt) rather than plaintext client network addresses.
7. **Internal Administrative Bypass:** The `obfuscatedHood` masking constraint applies exclusively to external queries, public search interfaces, and unconfirmed seeker agents. Authenticated internal tenant personnel (administrators, staff, and internal agency brokers) possess automatic, unrestricted bypass to view plaintext property addresses and exact coordinates across all administrative consoles and internal API calls.

## Verification

1. Submit a property description payload containing a test CPF number `123.456.789-00` to the ingestion pipeline; assert record is rejected with `REJECTED_PII_DETECTED`.
2. Configure tenant with `obfuscatedHood: true`. Query property via public search; assert response payload contains neighborhood name (`Pinheiros`) and centroid, but fields `street_address`, `number`, and `exact_coordinates` are null.
3. Submit search request with a confirmed viewing booking token; assert full address is returned.
4. Authenticate as an internal agency broker on the tenant administrative console; retrieve the same listing configured with `obfuscatedHood: true`; assert `street_address`, `number`, and `exact_coordinates` are returned in plaintext without obfuscation.
