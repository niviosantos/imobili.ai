# Multi-Tenant Data and Index Isolation

This requirement establishes non-negotiable boundaries for logical and cryptographic isolation between independent real estate tenant environments in the Imobili.ai platform, strictly prohibiting cross-tenant shared pools.

---

## Statement

The platform must enforce strict multi-tenant isolation across all persistent databases, high-dimensional vector index collections, cache partitions, and runtime process spaces. Cross-tenant federated search pooling, shared vector indices, or shared inventory aggregations are strictly prohibited (No Shared Pools invariant). No tenant query, agent action, or background worker may access, infer, or aggregate data belonging to another tenant under any circumstance.

---

## Rationale

In a decentralized PropTech ecosystem, real estate brokerages store proprietary inventory, customer leads, pricing thresholds, and confidential negotiation strategies. Shared multi-tenant pools create unacceptable risks of competitor data extraction and listing leakage. By enforcing a strict "No Shared Pools" architecture, each brokerage maintains an absolute data sovereign boundary.

## Measurable acceptance criteria

1. **Vector Index Partitioning:** Every tenant vector collection must be created with a distinct collection name matching `imob_<tenant_id>_vectors` and isolated namespace keys. Shared or global vector collections are prohibited.
2. **Access Control Authorization:** Every programmatic A2A query must be verified against tenant credentials before executing similarity search. Unauthorized cross-tenant queries must return HTTP status `403 Forbidden`.
3. **Storage Encryption:** Persistent property records and embedding stores must be encrypted at rest using distinct encryption key references per tenant (`vault://keys/<tenant_id>`).
4. **Data Purge Integrity:** Tenant teardown operations must irreversibly purge the tenant vector collection and storage partition without affecting adjacent tenant data structures.
5. **No Shared Pool Invariant:** Ingestion pipelines and search endpoints must reject any configuration flag attempting to bridge, link, or aggregate vector embeddings across distinct tenant IDs.
6. **Client-Side Aggregation Boundary (Out of Scope for Server):** The platform server explicitly delegates cross-tenant listing aggregation, deduplication, and multi-brokerage score ranking to external consumer client agents. The server platform provides zero server-side federation, cross-tenant pooling, or cross-brokerage result merging.
