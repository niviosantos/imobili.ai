# User Story: Parameterized Property Search Execution via A2A

---

## Summary

- **As an** AI agent powering an automated real estate search engine,
- **I want to** submit a structured A2A request containing specific search filters (property typology, geographic region, transit amenities, budget ceiling, bedroom minimums),
- **So that** I receive an accurate list of matching properties ranked by semantic relevance with automated dynamic irrelevance floor filtering, without needing manual threshold configuration.

---

## Scope in/out

- **In Scope:** JSON-RPC query dispatch to `/api/v1/a2a/search`, hybrid execution combining structural SQL metadata with vector similarity scoring, automated dynamic irrelevance floor pruning, applying `obfuscatedHood` privacy masking, and supporting zero-match fallback responses.
- **Out of Scope:** Final contract signing, payment escrow processing, and physical viewing key exchanges.

---

## Preconditions

1. External agent has discovered capabilities via `agent-card.json` per [[sto-202609131605]].
2. Tenant vector database collection initialized per [[run-202609121908]].
3. Semantic search architecture operational per [[con-202609121901]].
4. Compliance with LGPD privacy masking and `obfuscatedHood` tenancy configuration per [[req-202609121913]].

## Expected behavior

When an external agent transmits a valid JSON-RPC search payload to `/api/v1/a2a/search`, the system queries the tenant's isolated vector and metadata indices, filters properties according to hard constraints, computes semantic relevance with a dynamic irrelevance floor, masks exact addresses to neighborhood centroids if `obfuscatedHood: true`, and returns a structured array of matching properties.

---

## Acceptance criteria

### Criterion 1: JSON-RPC Dispatch Processing
- **Given** an external AI agent with discovered search parameters,
- **When** the agent posts a valid JSON-RPC 2.0 request payload to `/api/v1/a2a/search`,
- **Then** the platform must return HTTP status `200 OK` and a JSON-RPC 2.0 result object.

### Criterion 2: Supported Search Parameters
- **Given** an incoming search payload,
- **When** the request includes fields `property_type`, `region`, `amenities`, `bedrooms_min`, and `price_max`,
- **Then** the platform must execute hybrid filtering matching all specified constraints.

### Criterion 3: Hybrid Retrieval with Dynamic Irrelevance Floor
- **Given** search query embeddings and vector candidate matches,
- **When** k-NN nearest neighbors are scored,
- **Then** the search engine must automatically calculate an adaptive dynamic irrelevance floor (pruning items below the knee/elbow of the score distribution), ensuring anonymous seekers receive high-relevance listings without manually specifying threshold cutoffs.

### Criterion 4: `obfuscatedHood` Privacy Enforcement
- **Given** a tenant instance with `obfuscatedHood: true`,
- **When** property search results are serialized for public/unauthenticated seekers,
- **Then** each item must mask the street name and number, displaying only the neighborhood name (`region`), neighborhood centroid, and relevance score per [[req-202609121913]].

### Criterion 5: Zero Match and Sub-0.40 Floor Handling
- **Given** query filters that match zero listings or where all candidates fall below the dynamic irrelevance floor (or top candidate score is below the 0.40 absolute floor),
- **When** the search is processed,
- **Then** the platform must return HTTP status `200 OK` with an empty array `[]` in `result.items`, `result.total: 0`, and `irrelevance_floor_applied: 0.40` without returning an HTTP or JSON-RPC error.

## Contracts and data

- **Endpoint:** `POST /api/v1/a2a/search`
- **Request Format:** `application/json` (JSON-RPC 2.0)
- **Example Request (Anonymous / Public Tier):**
```json
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "method": "search_properties",
  "params": {
    "property_type": "apartment",
    "region": "Pinheiros",
    "amenities": ["subway", "bakery"],
    "bedrooms_min": 2,
    "price_max": 4500.00
  }
}
```
- **Example Response (with `obfuscatedHood: true`):**
```json
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "result": {
    "total": 1,
    "irrelevance_floor_applied": 0.78,
    "items": [
      {
        "id": "prop-sp-042",
        "title": "Apartment near Fradique Coutinho Station",
        "region": "Pinheiros, Sao Paulo, SP",
        "address": "Pinheiros (Exact address masked per tenancy policy)",
        "price": 4200.00,
        "relevance_score": 0.94,
        "canonical_url": "https://alpha.imobili.ai/properties/prop-sp-042"
      }
    ]
  }
}
```

## Business rules

1. All searches must execute strictly within the tenant collection partition mandated by [[req-202609121910]] (No Shared Pools).
2. Requests must comply with rate limiting quotas specified in [[req-202609121912]] (Tier 1 Public/Anonymous: max 30 req/min per IP; Tier 2 Registered Agent with `X-Agent-Key` or `X-Agent-Signature`: max 120 req/min; no VIP tier).
3. Unmasked owner contact information, exact street numbers (under `obfuscatedHood: true`), and national ID numbers must never appear in response payloads per [[req-202609121913]].
4. The dynamic irrelevance floor must execute by default on all queries (`cutoff = max(0.40, top_score - 0.25)`). If the top score falls below 0.40 (`top_score < 0.40`), the search engine returns `total: 0, items: []` with `irrelevance_floor_applied: 0.40`. Clients may optionally supply an explicit `min_relevance_score` parameter, but if omitted, the dynamic floor is calculated autonomously.

---

## Edge cases and errors

- **Invalid Parameter Types:** If `price_max` is negative or non-numeric, return JSON-RPC error code `-32602` (`Invalid params`).
- **Database Timeout:** If vector search backend exceeds 1500 ms latency, return graceful degraded SQL fallback results with header `X-Search-Mode: fallback-lexical`.
