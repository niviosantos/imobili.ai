# Cryptographic Audit Trail and Transaction Integrity

This requirement governs the cryptographic verification, registered account enforcement, internal agency validation workflows, and tamper-evident recording of all programmatic interactions and contractual offers between autonomous agents.

---

## Statement

Every Agent-to-Agent (A2A) transaction—including agent card discovery declarations, parameterized search requests, scheduling locks, and purchase or rental proposals—must be cryptographically signed by the originating identity and recorded in an immutable audit trail. To prevent scams, spam bids, and fraudulent transactions, submitting an offer strictly mandates a prior verified user account on the tenant platform, and all offers must pass through an internal brokerage validation workflow before binding contractual acceptance.

---

## Rationale

Autonomous agents negotiate on behalf of human principals and corporate entities. In case of pricing disputes, scheduling collisions, or contract execution verification, the platform must guarantee non-repudiation and complete traceability back to the initiating agent's cryptographic signature. Requiring registered accounts and internal broker review eliminates automated spam bidding and ensures legal enforceability.

## Measurable acceptance criteria

1. **Prior Account Registration Mandate:** Any A2A endpoint processing an offer (`POST /api/v1/a2a/negotiate` or `/offer`) must reject unauthenticated or unverified users with HTTP status `401 Unauthorized` and error code `ACCOUNT_REGISTRATION_REQUIRED`.
2. **Internal Brokerage Validation Workflow:** Received offers must initially enter a `PENDING_AGENCY_VALIDATION` state, routing to the agency internal workflow for manual broker review and credit/fraud validation before progressing to `ACCEPTED` or `COUNTERED`.
3. **Transaction Non-Repudiation:** Every transactional proposal payload must include an asymmetric signature header (`X-Agent-Signature`) resolvable to the registered user or agent's public key.
4. **Immutable Log Appending:** Transaction logs must be written sequentially with SHA-256 cryptographic chaining to prevent retrofitting or tampering.
5. **Signature Verification Failure:** Incoming transactional payloads with invalid, expired, or missing cryptographic signatures must be rejected immediately with HTTP status `401 Unauthorized`.
6. **Asynchronous Status Polling Endpoint:** The platform must provide an authenticated query endpoint (`GET /api/v1/a2a/offers/{offer_id}`) allowing originating agents to poll the validation status on demand. The response payload must return the current lifecycle state (`PENDING_AGENCY_VALIDATION`, `ACCEPTED`, `REJECTED`, `EXPIRED`), broker feedback or counterproposal data, and timestamp of the latest transition.

## Verification

1. Transmit an offer payload from an unregistered client or without an account token to the `/api/v1/a2a/negotiate` endpoint; assert request fails with HTTP `401 Unauthorized`.
2. Transmit an offer payload signed by a valid registered account; assert status is `200 OK` and offer record is created with state `PENDING_AGENCY_VALIDATION`.
3. Query `GET /api/v1/a2a/offers/{offer_id}` as the originating agent; assert response returns HTTP 200 with current state `PENDING_AGENCY_VALIDATION`.
4. Transition offer to `ACCEPTED` in broker dashboard; poll `GET /api/v1/a2a/offers/{offer_id}`; assert response immediately reflects state `ACCEPTED`.
5. Verify that the offer submission event is immutably appended to the tenant audit log with valid SHA-256 block hash within 100 milliseconds.
